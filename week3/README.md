# 천 개의 할 일

와플스튜디오 2026 프론트엔드 세미나 3주차 과제입니다. 별도 서버 없이 브라우저에서 동작하는 React 앱이며, PDF의 화면 예시를 바탕으로 반응형 UI를 구성했습니다.

## 실행

Node.js 22 이상에서 저장소를 내려받고 다음 명령을 실행합니다.

```bash
cd week3
npm ci
npm run dev
```

```bash
npm test                 # 저장/수정/보관/검증/천 개 데이터 단위 테스트
npm run build            # 프로덕션 빌드
npx playwright install chromium
npm run test:e2e         # 실제 브라우저 테스트
```

의존성 버전은 `package-lock.json`으로 고정했습니다. GitHub Actions에서 단위 테스트 6개, 프로덕션 빌드, 브라우저 시나리오 5개를 검증합니다.

## 구현 기능

- 할 일 추가 및 제목을 눌러 수정, 전체/공부/운동/집안일 필터
- 체크박스 완료/해제, 취소선, 완료한 항목만 보관하기
- 생성일과 실제 체크한 완료일을 보관함에 표시
- 완료일 날짜 검색 및 최근/오래된 완료순 정렬
- 모든 화면과 모달의 다크 모드, 새로고침 후 복원
- 닫기 버튼/Esc/바깥 영역 클릭 시 초안 유지, 취소/저장 시 해당 초안 삭제
- 신규 초안과 할 일별 수정 초안을 분리하여 서로 덮어쓰지 않음
- 확인 모달을 거친 앱 데이터 전체 초기화 (다른 앱의 저장값은 보존)
- 빈 상태, 입력 검증, 저장 오류 안내, 키보드 접근 및 모바일 레이아웃

## 스토리지 선택 이유 (PR 제출용)

할 일 목록·보관함·다크 모드는 브라우저를 다시 열어도 유지되어야 하므로 `localStorage`를 사용했습니다. 천 개 수준의 짧은 텍스트 데이터에 충분하며, 목록과 보관함을 하나의 스냅샷으로 저장하여 보관 시 중간 상태가 남지 않게 했습니다.
아직 확정하지 않은 입력값은 `sessionStorage`에 별도로 저장해 같은 탭에서 모달을 닫거나 새로고침해도 복원되지만 세션이 끝나면 정리되도록 했습니다.

## 전역 상태 관리 선택 이유 (PR 제출용)

앱 규모가 작고 할 일·테마·보관함을 여러 화면에서 함께 사용하므로 React Context를 선택했습니다. Provider에서 저장 동작과 상태 변경을 관리해 props drilling을 피하고, 순수 reducer로 추가·수정·완료·보관 로직을 분리하여 테스트하기 쉽게 했습니다.
필터·모달 표시 여부처럼 한 화면에만 필요한 값은 로컬 상태로 유지했습니다.

## 구조

- `src/model.js`: 데이터 검증, 순수 상태 전이, 날짜 검색/정렬
- `src/Store.jsx`: Context, 저장소 읽기/쓰기, 초기화 및 오류 처리
- `src/App.jsx`: 메인/설정/보관함/추가·수정 모달
- `src/index.css`: Tailwind import 및 공통 컴포넌트 스타일
- `tests/`: Node.js 단위 테스트
- `e2e/`: Playwright 기능 시나리오

## 확인 방법

1. 할 일을 추가한 후 새로고침하여 유지되는지 확인합니다.
2. 모달에 입력 후 닫기와 새로고침으로 복구하고, 취소 시 지워지는지 확인합니다.
3. 카테고리를 변경하고 필터 결과를 확인합니다.
4. 완료/해제 후 다시 완료하여 보관하고 생성일/완료일을 확인합니다.
5. 설정에서 다크 모드를 켜고 메인/모달/보관함과 새로고침 후 상태를 확인합니다.
6. 초기화 확인 창에서 취소 시 유지되고 모두 삭제 시 초기 상태로 돌아오는지 확인합니다.

브라우저/기기 사이 동기화는 하지 않습니다. 여러 탭의 동시 편집 병합은 지원하지 않으므로 한 탭에서 사용하세요. 브라우저 저장소를 지우면 데이터가 삭제됩니다. 손상된 저장값을 읽었을 때는 자동으로 덮어쓰지 않고 오류를 표시하며, 설정의 초기화로 복구할 수 있습니다.
